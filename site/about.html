Framework Story

Explain why A# exists, then show the source.

The web already has languages for structure, presentation, and behavior. A# explores how far a modern framework can go while keeping those languages recognizable.

Why A# Exists

The problem

Modern frameworks are powerful, but developers often learn several layers at once: framework syntax, component syntax, build configuration, router conventions, rendering models, state libraries, bundlers, and framework-specific server abstractions.

A# asks how much framework capability can be provided while preserving the mental model a developer already has from learning the web.

The Approach

Framework principles

  1. Web standards first — native platform capabilities over invented abstractions.
  2. HTML remains HTML — no JSX or proprietary template syntax.
  3. CSS remains CSS — associated, scoped, and bundled without being replaced.
  4. JavaScript remains JavaScript — framework APIs compose naturally.
  5. Convention over configuration — directory and file naming convey intent.
  6. Simple things stay simple — a basic page needs no DI, hydration, or global state.
  7. Complexity is available when needed — larger applications can reach further.
  8. Errors should teach — diagnostics explain what, where, why, and how to fix it.
  9. Native ecosystem compatibility — npm remains the package manager.
  10. Abstractions must earn existence — justified by real developer value.

Open-Source Philosophy

Where A# is going

V1 proves the core model: creating, running, routing, composing, styling, debugging, building, and previewing a real application without introducing a new authoring language. What comes after — reactivity, dependency injection, forms, rendering strategies, server capabilities — expands on that foundation without destabilizing it.
